# AINews 邮件订阅 · 部署说明

自助订阅/退订采用 **Cloudflare Worker + GitHub PAT** 方案：静态 GitHub Pages 站点无后端，
由 Worker 充当轻量 API，直接读写仓库内的 `data/subscribers.json`。发送端（`mail/send_digest.py`）
已自动合并该名单，无需额外改动。

## 一、架构

```
浏览器(网站订阅弹窗) ──POST /subscribe|/unsubscribe──▶ Cloudflare Worker
                                                            │
                                                            │ GitHub Contents API (PAT)
                                                            ▼
                                              main 分支 data/subscribers.json
                                                            │
        crawl-news.yml (早班) ──send-digest job──▶ 读 subscribers.json ──▶ Resend 群发
```

## 二、部署 Cloudflare Worker

1. 安装 wrangler：`npm install -g wrangler`（需 Node.js）
2. 登录：`wrangler login`
3. 进入 `worker/` 目录，设置仓库变量（已在 `wrangler.toml` 配好，按需改 `REPO`）：
   - `REPO` = `你的用户名/你的仓库`（默认 `aispiderwork/AINews`）
   - `PATH` = `data/subscribers.json`
4. 设置敏感 Secret（**不要**写进文件）：

   ```bash
   cd worker
   # GitHub PAT，权限需 public_repo（公开仓库）或 repo（私有仓库）
   wrangler secret put GH_TOKEN
   # 32 字节随机密钥的 base64（用于加密订阅邮箱，发送端需同一把密钥解密）
   wrangler secret put EMAIL_KEY
   # 任意字符串盐值（仅用于哈希去重，与发送端无需一致）
   wrangler secret put EMAIL_SALT
   ```

   - `GH_TOKEN`：GitHub Personal Access Token。GitHub → Settings → Developer settings → Personal access tokens → Generate new token (classic)，勾 `public_repo`。
   - `EMAIL_KEY`：生成命令 `openssl rand -base64 32`。**这把密钥必须同时配置到两处**——Cloudflare Worker（`wrangler secret put EMAIL_KEY`）和 GitHub Actions Secret（`EMAIL_KEY`，见第六节），否则发送端无法解密订阅邮箱。
   - `EMAIL_SALT`：任意字符串，如 `openssl rand -hex 8`。

5. 部署：`wrangler deploy`
6. 记下分配的 Worker 地址，形如 `https://<你的子域>.workers.dev`

## 三、配置网站前端

`index.html` 中的 `SUB_WORKER_URL` 已填入实际部署地址（本项目为 `https://spidernews.workers.dev`）。
若你重新部署或换子域，打开 `index.html` 修改该行：

```js
const SUB_WORKER_URL = 'https://你的子域.workers.dev';
```

推送后，网站「订阅」按钮即可直接调用 Worker。

## 四、CORS 来源

`worker/worker.js` 的 `ALLOWED_ORIGINS` 已包含：
- `https://aispiderwork.github.io`（生产站点）
- `http://127.0.0.1:5500` / `http://localhost:5500` / `:49295`（本地调试）

若你用**自定义域名**托管站点，请把该域名加入 `ALLOWED_ORIGINS`，否则浏览器会拦截跨域请求。

## 五、4 种 case 处理（由 Worker 服务端校验）

| 操作 | 情况 | 返回 code | 前端提示 |
|---|---|---|---|
| 订阅 | 新邮箱 | `subscribed` | 订阅成功 |
| 订阅 | 已订阅 | `already_subscribed` | 该邮箱已订阅，无需重复订阅 |
| 退订 | 已订阅 | `unsubscribed` | 已退订 |
| 退订 | 未订阅 | `not_subscribed` | 该邮箱尚未订阅，无需退订 |

## 六、隐私设计（已落地：只存哈希 + 密文）

`data/subscribers.json` 由 Worker 经 GitHub API 写入，**会绕过本地 `.gitignore`、成为仓库内可见文件**。
但**仓库里不直接存明文邮箱**，每条记录仅含：

- `h`：`sha256(EMAIL_SALT + "|" + email)` 的十六进制——仅用于去重/查重，**不可逆**，拿到也无法反推邮箱；
- `e`：`email` 经 **AES-256-GCM（EMAIL_KEY）** 加密后的 base64（iv 在前、tag 在后）——**只有持有 EMAIL_KEY 的发送端能解密**用于发信。

因此即便仓库是公开仓库，任何人克隆也只能看到哈希与密文，无法直接拿到订阅者邮箱。
发送端（`mail/send_digest.py`）在 `send-digest` job 中以 GitHub Actions Secret `EMAIL_KEY` 解密 `e` 后群发。

**注意**：`EMAIL_KEY` 是恢复订阅邮箱的唯一密钥——**请妥善备份**。若 `EMAIL_KEY` 丢失，已加密的 `e` 将无法解密，需让用户重新订阅。
`EMAIL_SALT` 丢失不影响解密，但已存的 `h` 将无法再匹配（老用户退订需重新订阅）。

**GitHub Actions Secret 配置**：除 Cloudflare 外，还需在 GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret，新增：
- `EMAIL_KEY`：值与上面 `wrangler secret put EMAIL_KEY` 用的**完全相同**（发送端靠它解密 `e`）。
`crawl-news.yml` 的 `send-digest` job 已注入该 Secret。

可选进一步增强（当前未做）：
- 将仓库设为私有（最彻底，但 GitHub Pages 公开站点需配合自定义域名/私有页白名单）；
- 或接受当前哈希+密文方案（推荐，内测足够）。

## 七、本地调试

- 不配置 `SUB_WORKER_URL` 时，前端点击会提示「服务未配置」，不报错。
- `mail/send_digest.py` 仍可用本地 `data/subscribers.json`（gitignored 样本）调试发送。
- 想本地起 Worker：`cd worker && wrangler dev`（需本地有 GH_TOKEN 环境变量或 secret）。
