# AINews 项目概要

## 一、项目定位

AINews 是一个 **AI 新闻聚合站点**：定时从多个中英文 AI 资讯源抓取新闻，经过去重、时间排序后输出为 JSON 数据文件，由纯静态前端页面直接读取展示。整套系统零服务器成本，依赖 GitHub Actions 定时运行 + GitHub Pages 托管。

## 二、主要能力

- 多平台 AI 新闻聚合采集（6 个数据源），输出统一格式的 JSON
- 按发布时间全局/分平台排序；常规平台保留近 7 天最新 Top 10，HuggingFace 保留论文 10 + Trending 模型 10
- 新旧数据增量合并，按 URL 去重
- 前端可视化：`index.html` 提供「头版 / 分平台」报纸风格新闻列表（含封面图、HN 真实互动数据），HuggingFace 内设「全部 / 论文 / 模型」子标签；另有运行监控看板（成功率、失败率、响应时间、封面获取率）
- GitHub Actions 定时自动运行，爬取结果自动提交回仓库并发布
- 支持手动触发与单平台抓取（`python main.py <platform>`）

## 三、主要数据源

| 平台 | 抓取方式 | 来源 | 爬虫文件 |
|---|---|---|---|
| Hacker News | 官方 Firebase API | `hacker-news.firebaseio.com/v0/topstories.json` + item API | `crawlers/hackernews.py` |
| 量子位 | HTML 解析 | `www.qbitai.com` | `crawlers/qbitai.py` |
| RadarAI | HTML 解析 | `radarai.top/updates/` | `crawlers/radarai.py` |
| BestBlogs | 官方 OpenAPI v2 | `api.bestblogs.dev/openapi/v2` | `crawlers/bestblogs.py` |
| HuggingFace | 官方公开 API | `huggingface.co/api/daily_papers` + `/api/models?sort=trendingScore` | `crawlers/huggingface.py` |

>
> 变更说明（2026-08-11）：TechCrunch、新智元两个渠道已从项目中移除（AI 关联度不高且信息冗余）；BestBlogs 已接入，抓取每日早报与热门精选两个子栏目，前端以「全部 / 早报 / 精选」子标签展示，`merge.py` 对 BestBlogs 保留最多 20 条，其中「精选」内容按热度/质量推荐、不受 7 天时间窗限制。

## 四、排序机制

> 变更说明（2026-07-28）：原 `hot_score` 综合热度分已**移除**。原因：除 Hacker News 外，其余平台均无真实互动数据，旧公式（平台权重×0.3 + 时间因子×0.4 + HN热度×0.3）本质是主观权重与时间衰减的合成值，展示"热度 0.xxx"会误导读者。详见 `main.py` 排序处注释。

当前排序规则（按发布时间倒序）：

1. 全局 `sorted_all` 按 `publish_time` 降序（解析失败的文章排最后）
2. 每个平台内部由 `crawlers/utils/merge.py` 先筛近 7 天文章，再按发布时间取 Top 10；HuggingFace 论文遵此规则，Trending 模型则直接按当前 trendingScore 热度参与排序与保留
3. HN 与 HuggingFace 文章保留真实互动数据：HN 保留 `score` / `comments_count`，HuggingFace 论文保留 `score` / `comments_count`、模型保留 `score` / `downloads` / `trending_score`，前端元信息行直接展示

## 五、爬虫实现方案

- **技术栈**：Python 3.11 + `httpx`（异步 HTTP）+ `BeautifulSoup4`/`lxml`（HTML 解析）+ `feedparser`（RSS）+ `python-dateutil`（依赖见 `requirements.txt`）
- **基类** `crawlers/base.py`：`BaseCrawler` 封装 4 个桌面 UA 随机轮换、30s 超时、`fetch`/`fetch_json` 方法；内置 `delay()` 但使用同步 `time.sleep` 且实际未被调用，整体无限速 / 重试机制
- **执行模型**（`main.py`）：`asyncio.run` 启动，但各平台按优先级 1–6 **串行**执行；单平台失败 try/except 隔离，不影响其他平台
- **统一处理策略**：每平台抓足量 → 筛近 7 天 → 平台内按发布时间排序 → 取 Top 10；HuggingFace 论文仍遵 7 天规则，Trending 模型按当前热度排序、不受 7 天创建时间限制，平台合计最多保留 20 条
- **去重 / 合并**（`merge.py`）：按 URL 去重，新数据覆盖旧数据；文章 ID 由 `md5(platform:title:url)[:12]` 生成；已下线平台（`REMOVED_PLATFORMS`）的旧数据不再合并
- **调度**：`.github/workflows/crawl-news.yml`，cron `0 1,12 * * *`（UTC 1:00 / 12:00，即北京时间 9:00 / 20:00，每天 2 次）+ `workflow_dispatch` 手动触发（可指定平台）

## 六、网站部署

- **纯静态站点**：无后端服务，前端 `index.html` 通过 `fetch('data/news.json?' + Date.now())` 直接读取 JSON
- **托管**：GitHub Pages，main 分支直接发布
- **CI/CD**：GitHub Actions 定时跑 `main.py`（`ubuntu-latest` + Python 3.11，pip 依赖用 actions/cache 缓存，job 超时 30 分钟），运行完成后由 `github-actions[bot]` 把 `data/news.json`、`data/history.json` commit 回仓库，GitHub Pages 自动更新

数据存储为纯 JSON 文件（`data/news.json` 主数据、`data/history.json` 执行历史，最多保留 100 条），无数据库——调研文档（`docs/crawler_research.md`）明确说明因 GitHub Pages 纯静态限制放弃了 SQLite 和 Playwright 方案。

## 七、技术栈总览

| 层 | 技术 |
|---|---|
| 爬虫 / 后端 | Python 3.11、asyncio、httpx、BeautifulSoup4、lxml、feedparser、python-dateutil |
| 存储 | 纯 JSON 文件，无数据库 |
| 前端 | 原生 HTML/CSS/JS 单文件（无框架、无构建），报纸风格设计（见 `docs/newspaper-style-redesign-plan.md`），另有 `poster.html`、`xiaohongshu-promo.html` 推广页 |
| 基础设施 | GitHub Actions（调度 + CI）+ GitHub Pages（托管），零成本 |

## 八、已知问题 / 注意事项

- README 与 `main.py` 注释称"每 6 小时"运行一次，实际 workflow 是每天 2 次，文档与配置不一致
- `crawlers/utils/filter.py` 为死代码，未被 `main.py` 调用
- `base.py` 的限速 `delay()` 未被任何爬虫使用，且无限速 / 重试机制
- 本地 `data/news.json` 最后更新时间为 2026-07-28；GitHub 会在仓库 60 天无活动时自动暂停 cron，需注意定时任务停更风险
